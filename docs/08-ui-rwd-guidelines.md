# UI / RWD 設計原則與驗收項目

> 第一階段完整賽事流程及未來所有前端開發，均需符合本原則。與 `.cursorrules` 第 4 節「前端開發規範」一致，此文件為正式驗收依據。

## 1. 核心原則

- **Mobile First**：所有 UI 設計必須優先考慮手機單手操作，再依斷點擴充平板與桌機。
- **觸控友善**：點擊區域至少 44×44px，避免過小按鈕或連結。
- **RWD 斷點**：使用 Tailwind 斷點 `sm`(640px)、`md`(768px)、`lg`(1024px)、`xl`(1280px)，確保各尺寸可讀可用。

## 2. 適用範圍

| 頁面類型 | 說明 |
|----------|------|
| 參賽者入口 | 報名、繳費、對局查詢、即時成績、個人戰績 |
| 主辦後台 | 賽事建立、報名／報到管理、編排、結果上傳、排名查詢 |
| 公開頁面 | 賽事列表、榜單、賽事詳情（含未登入瀏覽） |

## 3. 驗收檢查項目

### 3.1 版面與排版

- [ ] 手機直式（375px 寬）可完整瀏覽，無橫向溢出
- [ ] 表格／列表：小螢幕採卡片式或可橫向捲動，不強制固定寬欄
- [ ] 留白適當，減少認知負荷（符合 `.cursorrules` Visual Hierarchy）

### 3.2 互動元素

- [ ] 按鈕、連結、表單控件最小觸控區域 44×44px
- [ ] 重要行動（報名、報到、提交結果）在手機上一鍵可達

### 3.3 響應式模式

- [ ] 單欄／多欄依斷點切換（如 `grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`）
- [ ] 導覽在手機以漢堡選單或底部導覽呈現

### 3.4 無障礙與主題

- [ ] 支援 `prefers-color-scheme: dark` 深色模式
- [ ] 色彩對比符合基本可讀性要求

## 4. 技術實作

- **框架**：Next.js + React + TypeScript
- **樣式**：Tailwind CSS，使用 `sm:`、`md:`、`lg:` 等前綴
- **範例**：參考 `apps/web/src/app/page.tsx`、`ApiDemo.tsx` 既有 responsive 用法

## 5. 與第一階段 MVP 的關係

第一階段交付的「完整賽事流程」前端頁面（參賽者入口、主辦後台）須通過本章驗收項目，始可視為 MVP 完成。後續所有新頁面亦同。
